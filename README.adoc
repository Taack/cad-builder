= DSL for CAD Bodies and Assemblies
:icons: font

The purpose of this tool is to share 3D parts and assemblies like java class binaries.

As of today, the DSL is not complete to define bodies and assemblies will come later.

== Building

The native part requires https://github.com/Open-Cascade-SAS/OCCT[Open CASCADE Technology] 8.0 (C++17).
Use your distribution package if it ships 8.0, otherwise build it from source:

.Build OCCT 8.0.1 into a local prefix
[bash]
----
git clone --depth 1 --branch V8_0_1 https://github.com/Open-Cascade-SAS/OCCT.git occt
cmake -S occt -B occt/build -G Ninja -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_INSTALL_PREFIX=$HOME/.local/occt-8.0.1 -DUSE_FREETYPE=ON -DUSE_TBB=ON
cmake --build occt/build && cmake --install occt/build
----

Gradle looks for OCCT in `-PocctHome=<prefix>`, then the `OCCT_HOME` environment variable,
then `/usr` (Linux) or `/opt/homebrew` (macOS). It links every `TK*` toolkit found in `<prefix>/lib`.
To avoid passing it each time, add `occtHome=/home/<you>/.local/occt-8.0.1` to `~/.gradle/gradle.properties`.

.Run the tests
[bash]
----
./gradlew -PocctHome=$HOME/.local/occt-8.0.1 cad-dsl:test
./gradlew clean <1>
----

<1> To replay tests, you have to clean the env.

`display()` opens the shape in an interactive OCCT viewer window, `display("x.png")` renders it off-screen
(the images of this README are made this way), and `display("x.step")` / `display("x.stl")` export it.

NOTE: Without FreeImage support in OCCT (`-DUSE_FREEIMAGE=ON`), `display("x.png")` writes PPM data whatever the extension.

== Native Bindings

The Groovy code calls OCCT through a C API generated by jextract from
`cad-dsl-native/src/main/public/occt_capi.h`. This header is the only declaration of the
exported functions: the C++ implementation in `cad-dsl-native/src/main/cpp/capi/` includes it,
so a signature mismatch is a compile error.

* OCCT objects are opaque pointers; `OCCT_HANDLE(T)` is a heap-allocated `occ::handle<T>`.
* Release objects with `delete_<Type>`, handles with `delete_handle_<Type>`, and `double` arrays with `occt_free_doubles`.
* Flags are `int` (0 / 1).
* C++ exceptions never cross the boundary: a failing call returns `NULL` / `0`, and `occt_last_error()` gives the message.

== Sample

Get inspiration from https://github.com/CadQuery/cadquery[CAD Query], but using Groovy DSL.

.Sample Code
[source,groovy]
----
@Test
void "Pillow Block With Counterbored Holes and Prism"() {
    cd().box(length, height, thickness).topZ().wireFrom() {
        double rectSX = length - cboreInset
        double rectSY = height - cboreInset
        [[-rectSX / 2, -rectSY / 2], [0, rectSY],
         [rectSX, 0], [0, -rectSY]].each { double cX, double cY ->
            move(cX, cY)
            circle(centerHoleDia)
        }
    }.toFace().hole(-cboreHoleDiameter).topZ().wireFrom() {
        circle(centerHoleDia)
    }.toFace().prism(cboreHoleDiameter).display()
}

----

== Packages

There are 3 main packages in `cad-dsl` src folder (both for tests and implementation).

* `org.taack.cad.binding` classes use direct OCCT symbol binding using JExtract. It is considered low-level, and should not be used when composing a new body.
* `org.taack.cad.builder` using the builder pattern, quick way to test builder limitation, this step helps to build a good DSL. This package should not be directly used.
* `org.taack.cad.dsl` using the visitor pattern to build the DSL. This should be used in production.

=== Helix

`helix(radius, pitch, height[, endRadius])` starts a helix around the current direction (a negative pitch makes it
left-handed, `endRadius` makes it conical). `wire(radius)` sweeps a circle along it, `profile(from) { ... }` sweeps
any closed profile drawn with the usual 2D edges. The profile lies in the axial plane at the start of the helix:
`x` goes away from the axis, `y` goes along it, and `(0, 0)` is the start point of the helix.

.Spring
[source,groovy]
----
@Test
void "Spring"() {
    cd().helix(10, 4, 40).wire(1).display()
}
----

.Bottle Threading
[source,groovy]
----
static CadDsl helixThreading(CadDsl s) {
    double depth = myNeckRadius / 12
    double pitch = myNeckHeight / 4

    Vec2d pOri = new Vec2d(-depth / 3, -pitch / 3)
    Vec2d p2 = new Vec2d(depth, -pitch / 12)
    Vec2d p3 = new Vec2d(depth, pitch / 12)
    Vec2d p4 = new Vec2d(-depth / 3, pitch / 3)

    s.fuse {
        position(new Vec(myHeight + pitch / 2)) {
            direction(new Vec(1))
            helix(myNeckRadius, pitch, myNeckHeight - 1.5 * pitch).profile(pOri) {
                edge(p2)
                edge(p3)
                edge(p4)
                edge(pOri)
            }
        }
    }.toCadDsl()
}
----

=== Wings and Propellers

`wing { ... }` lofts through the sections declared with `section(leadingEdge, chord[, twist])`. From the current
position, the chord goes along X, the span along Y and the thickness along Z. Each section is drawn for a unit chord
(`x` from the leading edge at 0 to the trailing edge at 1, `y` for the thickness) with `profile(from) { ... }`, where
`spline(...)` draws a smooth curve through points, or with `naca('2412')` for a NACA 4-digit airfoil. It is then
scaled to the chord, twisted in degrees around the quarter chord (positive nose up) and moved to its leading edge.

.Wing with Free Profile Sections
[source,groovy]
----
@Test
void "Wing with Free Profile Sections"() {
    Vec2d te = new Vec2d(1, 0)
    Vec2d le = new Vec2d(0, 0)

    cd().wing {
        section(new Vec(), 2).profile(te) {
            spline(new Vec2d(0.5, 0.09), new Vec2d(0.15, 0.08), le)
            spline(new Vec2d(0.15, -0.04), new Vec2d(0.5, -0.03), te)
        }
        section(new Vec(0.3, 5, 0.3), 1.6, -1).profile(te) {
            spline(new Vec2d(0.5, 0.08), new Vec2d(0.15, 0.07), le)
            spline(new Vec2d(0.15, -0.035), new Vec2d(0.5, -0.025), te)
        }
        section(new Vec(0.9, 8, 0.8), 0.8, -3).profile(te) {
            spline(new Vec2d(0.5, 0.06), new Vec2d(0.15, 0.05), le)
            spline(new Vec2d(0.15, -0.03), new Vec2d(0.5, -0.02), te)
        }
    }.display()
}

`circularPattern(count[, axis]) { ... }` repeats the solids made in its closure around an axis (Z by default) through
the current position; the copies join the enclosing `fuse`, `cut` or `common`. With `CadDslWing.pitchTwist(pitch, radius)`,
which gives the twist of a blade section for a propeller pitch, it makes propellers:

.Three-blade Propeller
[source,groovy]
----
@Test
void "Three-blade Propeller"() {
    double hubRadius = 1.5
    double hubLength = 3
    double pitch = 6
    double tipRadius = 8
    // chord along the blade, from the root (inside the hub) to the tip
    Map<Double, Double> chords = [1.2d: 1.2d, 3d: 1.6d, 5.5d: 1.3d, 8d: 0.5d]

    cd().position(new Vec(-hubLength / 2)) {
        cylinder(hubRadius, hubLength)
    }.fuse {
        circularPattern(3) {
            wing {
                chords.each { double r, double chord ->
                    // quarter chord on the blade axis, twisted like a helix of the propeller pitch
                    section(new Vec(-chord / 4, r, 0), chord, CadDslWing.pitchTwist(pitch, r)).naca(r < tipRadius ? '4412' : '0010')
                }
            }
        }
    }.display()
}
----

== Distribution and Usage

`cad-dsl` has been published on maven for Linux x86 only.

=== Maven

Artifact coordinates:

.Maven
[source,groovy]
----
implementation 'org.taack.cad:cad-dsl:0.1'
----

NOTE: See https://github.com/Taack/cad-dsl-app/blob/main/cad-dsl-linux-app-x86-64/build.gradle[sample-build.gradle] to deal with JMOD files

You can also compile `cad-dsl-native` for your platform, and put the library in your lib path.

You can download a sample app https://github.com/Taack/cad-dsl-app/tree/main/cad-dsl-linux-app-x86-64[cad-dsl-linux-app-x86-64]
